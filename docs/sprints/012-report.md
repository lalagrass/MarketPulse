## 4. 我對實作端一個說法的更正：漏網區本輪一列都沒抓到

`012-evidence.md` §3.1 把 `6712 長聖 174.5 → 157.0` 稱為「§0.2 說的漏網區」。**不是。**
它的 `r = −10.0287%`，**`> 0.10` 這條線本來就看得到它**——它只是印出來被四捨五入成 `-10.0%`。

真正的漏網區是「|r| 落在 10% 以內、但超出實際漲跌停價」的那一段。規劃端把 273 筆
逐筆取出百分比排序：

```text
最小的 |r| = 10.0287%     |r| < 10.0% 的筆數 = 0
```

**一列都沒有。**所以本輪檔位表量到的效益，**全部來自移除偽陽性，沒有一筆是新抓到的斷點。**

這不減損 DO-2——1636 筆雜訊消失、6669 不再被埋，本來就是它的主要目的。
但「檔位表會抓到 `> 0.10` 看不見的東西」這句話在 441 個交易日的樣本上**沒有物證**，
不應該被下一輪當成既定事實繼承。漏網區在數學上仍然存在（`前收 9.98 → 漲停 10.95 = +9.72%`），

## 5. 本輪新產生／新浮現的問題（四項，全部進 backlog）

### 5.1 `data/raw/calendar/` 是不可再生資料，卻掛在為可再生資料寫的 ignore 規則下

```text
data/raw/calendar/2026.json   2,878 bytes
git check-ignore -v →  .gitignore:13:data/raw/*
```

`data/raw/` 那條 ignore 是為 836MB 的 EOD 快取寫的，而 **EOD 是可以重抓的**
（那些端點吃日期參數）。**這份日曆不行**——過去年度永遠取不到。
一次 `rm -rf data/raw`，2026 年的官方休市表就永久消失，而且沒有任何地方會出聲。

**它是這個 repo 裡第一份「小、且真的不可再生」的資料。**2.9 KB／年，
與「資料不該留在 git」那條理由（體積、可再生）**兩個前提都不成立**。
**建議 013：把 `data/raw/calendar/` 從 `.gitignore` 排除、納入版控。**

兩份同義邏輯放著，改一份忘另一份是遲早的事。刪掉，或讓內聯那段呼叫它。

**先記著不排**——沒有物證的效能項目不進 DO。
