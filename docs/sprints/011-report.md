## 2. 沒做到的：零項。但有兩件事比「沒做到」重要

### 2.1 DO-1 買到的資訊，比 spec 以為的少一半

分桶（實作端自己貼的，我複核算術）：

```text
|r| > 0.10                       1909
  其中 0.10 < |r| ≤ 0.101        1644   ← 漲跌停 × 檔位進位，86%
|r| > 0.101                       265
|r| > 0.15                         97
|r| > 0.41                         31    ← 單日就超過五日的理論下限
主題成員且 |r| > 0.15               3    ← 2327 國巨、3163 波若威、6669 緯穎
```

**這回答了拍板題 1 的讀法 (1)，但結構上回答不了讀法 (2)。**
台股除權息幅度多在 3–8%，**全部落在 ±10% 這條線以下**，`impossible_daily_returns`
看不見它們。所以「未還原收盤價有沒有系統性壓低高殖利率族群」這一題，
本輪一個字都沒買到——不是實作端沒做，是**題目用錯了尺**。這是規劃端的。

另一件我沒能驗、但要記下來的：`impossible_daily_returns` 的 prev close 是
`groupby("symbol").shift(1)`，取的是**上一筆有資料的日**。個股停牌時它會跨過空窗，
把多日報酬印成單日。265 筆裡有多少是這樣造成的，我在這邊算不出來。

### 2.2 DO-2 的判定，掛在一個不耐久的東西上

`fetched_before_session` 比的是**檔案 mtime**（`data.py:357-367`）。功能正確、
測試也釘住了，但那 32 個「官方休市」的判定，全部來自 2026-08-31 那一次批次回補
留下的 mtime。**一次 `cp -r`、一次備份還原、一次搬硬碟，32 個判定會同時失真，
而且不會有任何地方出聲。**

這不是本輪的缺陷——spec 只要求「說得出是哪一種」，它做到了。
但它把 backlog 那條「`data/raw` 可驗證清單（session date・校驗和・判定）」
從「好題目」升格成**這一條的前置**：現在有一個功能依賴 mtime 了。

## 5. 一個沒人要求、但數字自己跳出來的東西：σ 沒有它看起來的精度

多了**一個**交易日（n_days_used 386 → 388），k=1 的距離從 **+34.36σ 變成 +39.41σ**。
觀測值一動也沒動（0.9307），虛無平均幾乎沒動（0.0590 → 0.0597）——
**整個位移來自 null_std 從 0.0254 掉到 0.0221（−13%）**。

1000 次抽樣對標準差的估計誤差約 2%，所以這不是抽樣雜訊，是虛無分布本身對
「多一天」很敏感。無論成因是哪一個，讀出來的事情一樣：
**`CLAUDE.md` 那張表把 σ 印到小數點後兩位，而它在一個交易日的擾動下會動 15%。**

006-review 的 A1（`0/1000` 實際只有 288 個相異位移，窮舉更便宜也更誠實）從
2026-09-06 起就掛在 backlog 上，沒有物證推動它。**現在有了。**

## 6. 規則質疑 — D10，本輪的判準經過第一次實戰

011 spec 依 D10 的新判準引入 `LIMIT_MOVE = 0.10`（交易所規則，不是把手）。
實戰結果：**判準成立，但不完整。**

```text
物證：LIMIT_MOVE 沒有被調過（calc.py:44，註解引用 D10），1644 筆偽陽性
      原封列出——判準要求的「偽陽性不得靠調數字消除」被遵守了
詮釋：但 0.10 這條線本身用錯了。交易所規則不是「10%」，是
      「漲停價 = 前收 × 1.1，依檔位進位」——真正的規則帶著一張檔位表，
      而 0.10 是它的簡化版。簡化版製造了 86% 的雜訊
決定：判準不變（來源是交易所規則就不是把手），但補一句：
      **用規則的完整形式，不要用它的簡化版**——檔位表一樣是交易所規則
重看：012 驗收後
```
