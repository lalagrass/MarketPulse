## 要做的

### DO-1　用循環位移檢定，判斷 persistence_20 是否可與雜訊區分

**背景**
sprint 001 量到 `rank_persistence_20` 中位數 0.282、平均 0.214。n=11 時兩個獨立隨機
排列的 Spearman ρ 標準差約 0.316，所以單日看不出差別；而 121 個觀測高度重疊
（相鄰日共用 19/20 窗口），無法直接用常規標準誤檢定。

**做什麼**
新增 `marketpulse/quality.py` 的 `persistence_null_test(snapshot, k=20, n_iter=1000, seed=...)`，
用**循環位移**（circular shift）建立虛無分布：

- 觀測統計量：`mean over T of spearman(R[T], R[T-k])`，R 為 date × theme 的名次矩陣。
- 虛無：對每次抽樣取隨機位移 s，計算 `mean over T of spearman(R[T], R[(T-k+s) mod n])`。
- 循環位移**保留兩條序列各自的自相關結構**，只破壞它們之間的時間對齊——
  這正是自相關序列做時序關聯檢定的標準做法。獨立打亂會同時破壞日間連續性，
  產生錯誤的虛無寬度。
- 回傳：觀測值、虛無分布的平均與標準差、觀測值在虛無分布中的百分位。

同時輸出 `rank_persistence_20` 序列本身的圖，存為 `reports/persistence_20.png`。

**驗收條件**
1. `k=1` 時觀測值遠高於虛無分布（百分位 > 99）——這是健全性檢查，
   1 日持續性必然顯著，若不顯著代表實作有誤。
2. 位移 s 的抽樣範圍排除接近 0 與接近 n 的值（否則等同未位移）；
   以固定 seed 呼叫兩次結果相同。
3. 樣本不足以計算 `rank_persistence_k` 的日期不進入統計，且回傳值註明實際使用的日數。
4. 圖檔產生且橫軸為交易日、縱軸為 −1 到 1，有零線。

**會動到的檔案**：`marketpulse/quality.py`；`marketpulse/cli.py`（新增子指令或掛在 `analyze` 後）；
`marketpulse/product.py`（若圖表繪製共用既有 helper）

**必須新增的測試**：`tests/test_quality.py` 增加——
以人工建構的「完全持續」序列驗證百分位接近 100；
以人工建構的隨機序列驗證百分位落在中段；
固定 seed 的可重現性。

**本項不做**：不下「是雜訊」或「是輪動」的結論字樣。**輸出數字與圖，判讀留給 PO。**

### DO-2　多時間窗 RS 並列（RS5 / RS20 / RS60）

**做什麼**
`compute_snapshots()` 目前只算 `rs20`。增加 `rs5`、`rs60`，各自做獨立的橫斷面排名
（`rank_rs5`、`rank_rs60`），與既有 `rank` 並列。

**這不是綜合評分。**同一條公式換三個參數，三個排名**全部並列顯示，不挑最好的那個**，
沒有留下任何可調校的把手。主排名 `rank` 仍然只由 `rs20` 決定（R1 未變）。

**驗收條件**
1. `rs5` / `rs60` 的計算與 `rs20` 使用同一個 `n_day_return` 路徑，僅參數不同。
2. 歷史不足時回傳 NaN 而非以較短窗口替代。以現有 141 個交易日計算，
   `rs60` 約自第 61 個交易日起才有值——**驗收時回報實際可用天數**。
3. `rank_rs5` / `rank_rs60` 的排名規則與既有 `rank` 完全一致（RS 由大到小、
   同分以 theme_id 排序、NaN 不參與排名）。
4. 既有 `rank` 欄位的數值**完全不變**——現有測試須原封不動通過。
5. Brief 與 radar 顯示三個排名，格式由你決定，但**不得合併成單一數字或箭頭**。

**會動到的檔案**：`marketpulse/calc.py`（`SNAPSHOT_COLUMNS` 需擴充）；

**必須新增的測試**：`tests/test_rs.py` 或新檔——三個窗口的手算比對；
`tests/test_rank.py` — 三組排名各自的順序一致性；前視測試涵蓋新欄位。

**本項不做**：不加 RS10、RS120 或其他窗口。三個已經夠說明尺度差異，

2. ~~三個排名是三欄還是一格？~~ **已回答 2026-09-05：一格，三個數字，中間標記。**

   實測回報：三欄版約 102 欄、合併版約 103 欄，寬度差異可忽略——你自己指出
   這是資訊設計問題不是寬度問題，正確。

   **決定：一格內三個數字，依短到長排序 `R5 · R20 · R60`。**

   理由：資訊不在任何單一數字裡，在三者的**關係**——RS5 名次優於 RS60 代表轉強、
   反之代表退潮。而關係靠鄰近性讀。擠在一格裡，形狀一眼可辨：

   - `1·3·7` 五日領先、六十日落後 → 新起的強勢
   - `7·3·1` 六十日強、五日弱 → 正在退潮
   - `2·2·3` 三尺度一致 → 穩定的領導

   **中間那個（R20）必須視覺標記**——粗體，或只有它保留 `#` 前綴。契約 R1 明訂主排名
   是 RS20 的排名，另外兩個是脈絡不是同級排名。純合併會讓這個區分消失。

   **欄位標題必須寫明順序**（例如 `Rank R5·R20·R60`），不要讓人猜哪個是哪個。

   **紅線：不得加箭頭或任何方向指示。**看到 R5 優於 R60 就自動標 ↑，那是把三個數字
   塌縮成一個判斷，正是 R1 要擋的。讓數字自己構成形狀。

   文字版 radar 與 Brief 同此原則；純文字無法用粗體時，以 `#` 前綴區分主排名。
