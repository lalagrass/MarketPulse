## 1. 改了什麼（五處，`SKILL.md` 307 → 389 行）

### A. 階段 4 新增「驗收條件寫現象，不寫機制」 ← 本次最重要的一條

**這是這個 skill 目前唯一重複發作過的病，兩次都是規劃端造成的。**

| 輪 | spec 寫的（機制） | 實際結果 |
|---|---|---|
| 009 DO-3.1 | 「`敘事` 是全表唯一沒有欄寬的欄，補到寬度 10」 | `Momentum` 也沒欄寬；做完畫面零改變 |
| 010 DO-2 | 「`radar.html` 至少要能回答資料到哪一天」 | 100% 照做；而 `caught_up` 在「根本沒跑過 refresh」時顯示一切正常——正是原本要解決的情境 |

兩次的形狀完全一樣：**把觀察到的抱怨翻譯成規劃端自己的機制診斷，再把診斷當驗收條件交出去。**
實作端照做是對的，錯在題目。

**抄回來的檢查（Gherkin 官方自檢問句）：**寫完每條驗收條件問一次——
**「如果實作方式換掉，這句話要不要跟著改？」**要改，就是機制，打回重寫。
上表兩條都不通過這個自檢，而且**用一句話就檢查得出來**。

配套兩條：背景欄只能寫可重現的客觀現象（禁止「因為……所以系統應該……」，
抄 bug report 對 Actual Result 的規範）；驗收條件盡量寫成
「WHEN <可觀察情境> THEN <可觀察行為>」（抄 AWS Kiro 的 EARS 句式）。

### B. 階段 1「只看輸出」角色的抱怨要逐字進 spec，不要先翻譯

010 的兩件事都出自這個角色，**同一輪、同一個角色，翻譯過的那條就失效了**：

- 「`15.8pp (18%)` 前後兩個數字看不出關係」→ 原話幾乎照抄進 DO-1 → 成立
- 「週末打開會懷疑是不是系統壞了」→ 被翻譯成「顯示資料到哪一天」→ DO-2 落空

這是 A 的上游。A 是事後檢查，B 是不要在源頭就丟失資訊。

### C. 階段 0 的閘門改寫：不再停下來等

舊條文「上一份報告的決定沒回答就停下來問」已經跟 PO 2026-09-06 的明示衝突
（未答即照規劃端推薦的選項執行）。改為：**照預設執行，但本輪報告第一段必須列出
「上一輪未答、本輪照預設執行了什麼」**，讓它可見、可回溯、可推翻。
真正 50/50 又不可逆的仍單獨標成判讀題——差別只在沒答時它會被執行，不是把整輪卡住。

**重看條件寫進去了：**若出現「照預設執行了、但 PO 其實不同意」的案例，改回閘門。

### D. 輸出預算的單位定義死

010-spec 222 行，而規劃端**當場**用「正文 167 行（不含空行）」替自己解套。
上限的單位沒定義，等於沒有上限——**而規避它的人就是寫下它的人。**

改：以 `wc -l` 為準、含空行。並寫明**超出時搬去附錄、不要壓縮**——
`NNN-evidence.md` 無上限，那就是附錄。（Amazon 6-pager 的做法：本文硬上限、
附錄無上限，逼作者搬家而不是縮字體。這正好是這個 skill 已經有的結構，
只是從來沒講明 evidence 可以當附錄用。）

### E. 絕對規則補一條操作註記：動 git 之前先確認刪檔權限

規劃端在雲端工作階段預設不能刪檔，git 會在 `.git/` 留下清不掉的 `.lock`，
之後每個 git 寫入都失敗——010 收尾 merge 連續失敗四次才發現。
同一次收尾用 `git add -A docs/` 誤把長期未追蹤的 `docs/post/` 加進版控。
兩件都寫進去了：先要權限、收尾指名檔案。

### F.（順帶）009 提出的目視驗收預設值正式寫進 skill

009-report 第 6 節提議、010 首次適用、有效（15 個新測試名沒有一個承載目視宣稱）。
先前它只活在一份 sprint 報告裡，讀不到那份報告的人就不知道有這條。現在在 skill 裡了。

## 3. 考慮過但沒改的（留著，免得下次重想）

- **spec-kit 的「測試先行閘門」**（動工前先有一份 PO 認可過的失敗測試）。
  方向對，但**規劃端跑不了 `uv run pytest`**——「PO 認可過的失敗測試」在這個
  分工下沒有人能產生。等價的便宜替代就是 A 的自檢問句，已抄。
- **Shape Up 的 circuit breaker**（週期到了沒做完＝作廢重回 shaping）。
  規則清楚可抄，但**這個專案沒有時間盒，11 輪也沒有一輪做不完**。
  起因填不出來，按 skill 自己的標準不加。
- **給 SKILL.md 自己一個行數上限。**它現在 389 行，每輪全文載入。
  沒有任何一次失效可以歸因於它太長，所以不加——但記在這裡，
  **若某輪出現「skill 裡有一條沒被執行，因為讀的人漏掉了」，那就是起因。**
- **刪掉 NO-SPRINT 出口**（11 輪從未被選過）。它是出口不是約束，沒被選中
  不等於沒有 binding；且它的目的是結構性的（防止 skill 每次被叫起來都生一輪）。
  維持，但第 2 節已記明它是自創而非抄來。
- **刪掉階段 3 開場的「連續兩輪沒用過產品就必須排使用／工程債」。**同上，
  11 輪從未觸發。維持，標記為未受測。
