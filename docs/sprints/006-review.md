## 併之前要處理

### A1 — `0/1000` 的分母給不出 1/1000 的解析度

**物證。**`_null_shift_candidates(407, h, 60)` 回傳 288 個相異位移（`ret=70.8%` 就是 288/407）。
`rank_ic_null_test` 用 `rng.choice(candidates)` **有放回**抽 1000 次 → 虛無分布最多只有 288 個相異值。

**詮釋。**`0/1000` 實際只能代表 `0/288`，精確 p ≤ 1/288 ≈ 0.0035，不是 1/1000 ≈ 0.001。
這是 004 拿掉 `percentile 100.0` 的同一類問題：**顯示的精度超過設計能給的**。

**而且窮舉更便宜。**288 < 1000。六個通過的格子從 6000 次評估降到 1728 次，
以 evidence 的 67s / 6000 次推算約 19s。窮舉之後 `n_ge` 是精確計數、seed 問題消失、A2 自動不見。

**建議。**007 把抽樣換成窮舉全部 candidates。`persistence_null_test` 有同樣的設計（繼承來的，
004 已驗收過），要不要一併改是另一個決定——但兩邊不一致要寫進報告。

### A2 — 同一欄三格抽到完全一樣的 1000 個位移

**物證。**`rng = np.random.default_rng(seed)` 在 `(k, h)` 迴圈**內**。同一個 h 的
candidates 陣列相同、RNG 流也相同 → `(5,20)`、`(20,20)`、`(60,20)` 用的是同一組 1000 個 e。

**詮釋。**對單格推論無害，而且有一個好處：單獨重跑一格可以復現。
但六格的虛無不是獨立抽的，**跨格比較 σ 時誤差是耦合的**。報告裡要講一句，
否則會有人把六格當六個獨立證據。A1 的窮舉會讓這條消失。

spec DO-1 驗收條件 6 是「`refresh`／`brief`／`radar` 產物逐字元不變」。

## 不擋併，但要寫進報告的讀法

### B1 — 這個虛無移除了什麼、沒移除什麼

位移只保證 `|e| ≥ max(2h, 60)`，但主題強弱有**數月尺度**的慢結構。
`(60,20)` 的 `null_mean = +0.1084` 就是那個東西的量度——**虛無自己就有 0.108 的相關**。

所以這裡的 σ 回答的是「除了慢速的族群品質排序之外，還有沒有快速、時點特定的資訊」，
**不是**「RS 對未來有沒有預測力」。這句話沒寫進報告的話，`+2.70σ` 一定會被讀成後者。
它也解釋了為什麼 k=60 那排 σ 最低：它的虛無中心最高，因為 rs60 本身就是慢結構。

### B2 — 六格挑最大的，多重比較沒扣

`(20,5) +2.70σ` 是六格裡挑出來的。Bonferroni ×6 之後仍在（p 上界 0.0035×6 ≈ 0.02），
但六格彼此不獨立（A2、共用同一份資料），Bonferroni 偏保守，實際介於兩者之間。
**可以說「站得住」，不能說「證實」。**

### B3 — h=60 什麼時候第一次可量，算得出來

護欄要 `retained ≥ 50%`：candidates ≈ `n − 2L`，需 `n ≥ 4L = 480`。
現在 407 session，差約 73 個交易日 ≈ 3.5 個月，**約 2026 年 12 月中**。
這該寫成 UNKNOWN 的回頭日期，不是一句「資料不夠」。

### B4 — 005 的故事翻了，要在報告裡明講

`(60,20)` 裸值 `+0.1402` 與 `(20,20)` 裸值 `+0.1404` 幾乎相同，但一個 `+0.37σ`、一個 `+2.57σ`。
**同樣的觀測值、相反的結論。**005-report 的「對角線隨天期上升」是對 0 讀出來的假象，
要在 005-report 裡明白更正，不能只在 006 寫新結論。

還站得住的一句：**RS20 是全表唯一在虛無之上站得住的 k**（`(20,5)` 與 `(20,20)` 都 0/1000）。
這是維持 RS20 當 primary 的物證，不是換 rank 的理由。

## 小事

- **`n=342` 站錯位置。**guard-fail 格的第二子行是 `n={n_days}`，而其他格第二子行是 `null ±…`。
  橫著掃會看成「虛無用了 342 天」。把它挪到第四子行（其他格 `n=… ret=…` 的位置）即可。
- **`n_iter` 一名兩義。**DataFrame 欄位存的是 `len(valid_null)`，CLI 尾行印的是使用者傳入的參數。
  目前相等所以看不出來。改名 `n_valid`。
- **真實快照上的恆等性沒有回歸鎖。**`test_null_observed_equals_compute_rank_ic_bit_identical`
  用合成資料；真實快照那次（含 `0.14037651721575425`）是一次性人工物證。合理——沒有 fixture 可放——
  但下次動 `_rank_ic_rs_matrices` 時要知道沒有東西守著它。

## 規劃端自己造成的問題

1. **spec 驗收條件 4「某格 sigma 落在 ±3 以內」寫得太鬆。**實作端照字面做成
   `assert bool((passing["sigma"].abs() < 3).any())` ——九格裡有一格正常就綠，八格爆掉也綠。
   正確的斷言是**所有** passing 格都在 ±3 內。007 收緊。
2. **同一條驗收條件的前半段「固定單調順序 → sigma 明顯為正」根本不可能成立**（每天順序相同時
   任何位移都給 +1，`null_std=0`，sigma 是 0/0）。實作端換成慢速隨機漫步並標記為「spec 沒要求」——
   那不是 scope creep，是**修正我的錯**，第三類分類要改成「更正規劃端錯誤」。
3. **spec 沒有要求任何多重比較的處理**（B2），也沒有要求說明虛無移除了什麼（B1）。
   兩者都是判讀的必要條件，寫 spec 時漏了。
