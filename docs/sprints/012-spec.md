### DO-2　把 `LIMIT_MOVE = 0.10` 換成交易所的漲跌停價（買資訊）

**背景（可重現的客觀現象，規劃端已獨立驗過）。**011 印出 1909 筆「不可能的單日報酬」，
其中 **1640 筆（85.9%）印出來恰好是 `+10.0%` 或 `-10.0%`**。規劃端從
`data/raw/TWSE/` 直接回算三筆（1504 兩次、6442 一次），三筆都**恰好落在合法漲跌停價上**，
|r| 數學上**等於** 0.10，但 `calc.py:155` 的 `abs(...) > limit` 在 IEEE-754 下全部回 `True`。

**因此 `calc.py:41-43` 的註解是錯的**——它把成因寫成「檔位進位剛好超過線」，
但漲停價是無條件捨去、跌停價是無條件進位，之後的比率只會 ≤ 10%。
`011-report.md` §2.1 沿用了同一個錯誤歸因。**兩處都在本輪一併更正。**

**完整回算、逐筆數字與「為什麼修浮點還不夠」見 `012-evidence.md` §0.1–§0.2。**

**做什麼。**把「比率 vs 0.10」換成「收盤價 vs 交易所算出來的漲跌停價」，
用十進位算術（`decimal.Decimal` 或整數檔位）比，不用 float 比率。

普通股最小跳動單位（交易所規則，非把手，D10 的 011 判準適用）：

```text
價格 < 10        → 0.01        100 ≤ 價格 < 500  → 0.50
10 ≤ 價格 < 50   → 0.05        500 ≤ 價格 <1000  → 1.00
50 ≤ 價格 < 100  → 0.10        價格 ≥ 1000       → 5.00

漲停價 = 前收 × 1.1，無條件捨去到該價位帶的檔位
跌停價 = 前收 × 0.9，無條件進位到該價位帶的檔位
```

**驗收條件。**

- **WHEN** 對全樣本重跑，**THEN** 上表三筆（1504 兩次、6442）**都不再出現在清單上**。
- **WHEN** 對全樣本重跑，**THEN** `6669 緯穎 2026-09-02`、`2327 國巨* 2025-08-25`、
  `3163 波若威 2026-07-28` **仍在清單上**。
- **WHEN** 對全樣本重跑，**THEN** 清單筆數印出來，且**逐筆全貼進 evidence**。
  預期由 1909 掉到 300 以內；**若不是，照實印，不得為了對上這個數字加任何過濾。**
- `LIMIT_MOVE` 這個常數與它的錯誤註解一併移除或改寫；新的檔位表旁邊要註明
  來源是交易所規則（D10 判準）。
- **不改任何既有數字：**`theme_daily.parquet`、`market_daily.parquet`、
  `rotation_latest.png` 三個 sha256 前後相同，且 `compute_snapshots` 的 diff 為空。

**會動到的檔案。**`calc.py`，顯示字串在 `cli.py`。
**必須新增的測試。**檔位表的六個價位帶邊界值（含 10／50／100／500／1000 本身）；
上表三筆恰好漲跌停的不入選；一筆確實超出漲跌停價的入選。
**本項不做：**修 `shift(1)` 跨停牌空窗（backlog 另一項）、除權息量測、改價格方法（§8）。

### DO-3　休市判定改讀官方休市表，mtime 降為最後手段（工程・本輪 ENG 保留格）

**背景（可重現的客觀現象）。**011 DO-2 讓「官方休市」與「抓取失敗」可區分，
但判定依據是**檔案 mtime**（`data.py:357-367`）。32 個「官方休市」的判定全部來自
2026-08-31 那一次批次回補留下的 mtime，一次 `cp -r`／備份還原會同時失真且不出聲
（`011-report.md` §2.2）。backlog 已因此把「`data/raw` 可驗證清單」升格為前置。

**規劃端已查證的來源。**TWSE 官方「市場開休市日期」JSON
（`https://www.twse.com.tw/rwd/zh/holidaySchedule/holidaySchedule?response=json&yy=2026`，
`data[]` 每筆有 `date`／`名稱`／`說明`，2026 年 27 筆）。官方、免費、與現有 EOD 同源，
過 D13。**已 fetch 驗證存在且格式如上，原始回應摘要見 `012-evidence.md` §0.3。**

**這份表只有「排定的」休市。**颱風臨時停市不在裡面——`2026-07-10` 就是這種。
所以本輪的目標**不是**消滅 mtime，是把靠 mtime 判的日子從 32 天縮到少數幾天，
並讓剩下那幾天在畫面上是**明講的未知**，不是靜靜的假日。

**做什麼。**抓取並快取官方休市表（`data/raw/calendar/<yyyy>.json`），
`empty_session_verdicts` 的判定順序改成：

```text
1. 在官方休市表上           → 官方休市（可重現，不依賴 mtime）
2. 週末                     → 非交易日
3. 不在表上但無資料         → 未知：臨時停市或抓取失敗（mtime 僅作為線索，且要標明）
```

**驗收條件。**

- **WHEN** 對現有 33 個空日期跑 `empty_session_verdicts`，**THEN** 輸出印出
  「靠 mtime 才判得出來的日期共 N 天」，且 N 明顯小於 32；N 與那份日期清單貼進 evidence。
- **WHEN** 查 `2026-07-10`，**THEN** 它落在第 3 類（未知），**不是**第 1 類——
  因為它不在官方休市表上。若它落在第 1 類，代表表讀錯了。
- **WHEN** 查 `2026-09-01`，**THEN** 它仍判為抓取失敗或未知，**不得**回到「官方休市」。
- **WHEN** 官方表抓不到（離線、格式變更），**THEN** 退回 011 的 mtime 行為並出聲說
  「本次判定未使用官方休市表」，不得靜默退回。
- 快取檔存在時不重抓；`refresh` 每年最多抓一次。

**會動到的檔案。**`data.py`，快取路徑常數與顯示字串在 `cli.py`。
**必須新增的測試。**表命中 → 官方休市；表未命中且無資料 → 未知（含 2026-07-10 的
固定 fixture）；表抓取失敗 → 退回 mtime 且旗標為真。
**本項不做：**`data/raw` 校驗和清單、`normalize_all` 全量重解、`date.today()` 的
UTC／台北時差（三項都在 backlog，都不是本輪）。
