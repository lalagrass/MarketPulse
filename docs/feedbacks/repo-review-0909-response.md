## 3. 它說對、而且說得比 repo 自己狠的一件事：文件量

它的第 7 節（over-documentation）是這份 review 最值錢的部分，而且**當天 repo 自己也量到了**：

```text
docs/          21,514 行   ← 產品程式碼的 3.4 倍
tests/          7,323 行
marketpulse/    6,355 行
```

`skill-retro-2026-09-09.md` §1 的物證更難看：

> 009 加了「驗收條件寫現象不寫機制」這條規則，之後 **014 犯兩次、015 犯兩次**，
> 第七次就發生在那份 retro 自己身上。**規則加了七次，發作率沒降。**

兩邊看到同一個病，但**處方不同，而 repo 的比較對**：

| | review 的處方 | repo（016）的處方 |
|---|---|---|
| 做法 | 只留四層權威文件，其餘視為可丟棄的歷史 | `acceptance-check.sh` 掛 `Stop` hook，exit 2 擋住收工 |
| 假設 | 文件太多所以沒人遵守 | 規則寫在「只有讀的人自律才會執行」的地方，所以不會被執行 |
| 物證 | 無 | 七次規則、四輪發作、全部有 commit |

**刪文件不會讓規則被執行，強制執行才會。**不過它有一句要收下：
「Don't create another framework to manage the frameworks.」——016 本身就是新機制，
如果它變成第八條要人自律的規則，那就是這句話應驗。016 的驗收條件上限 8 條就是為此。

## 4. 它真正的新東西：只有 Phase C 一項

> **當 MarketPulse 說某族群強，之後通常發生什麼？**
> 到達 #1 之後 5／10／20 日的前向報酬、正報酬機率，並切片：
> `#1+改善`／`#1+轉弱`／`#2→#1`／`#5→#2`／`R5 #1 但 R20 #6`。

**這一項不在 backlog，值得排。**理由：

- 它跟 D2 不衝突。D2 的 2026-09-06 註記已經替 `rank-ic` 開過同一道門：
  **買資訊的診斷、不進 Brief／radar、不改 rank、不模擬進出場與損益**。條件式前向報酬同構。
- 它用的全是既有素材（`theme_daily.parquet` + 三個 rank + `rank_delta_5` + momentum 證據），
  零新相依、零新資料。
- 它比再加一個指標更接近使用者真正的問題。這點它說得對。

**但排之前有兩條硬前提，不寫進 spec 就會重犯已經犯過的錯：**

1. **要虛無基準。**003 曾把原始 IC 當結論、004 撤回重測——這是 repo 自己記在案的更正。
   條件式前向報酬更容易看起來很漂亮：11 個族群 × 369 個 session，
   「#1」只有一條序列、窗口重疊，切完片每格的**獨立**事件數大概是十位數，不是三百。
   沒有循環位移（或 block bootstrap）對照就不准印。
2. **D6 的偏誤方向要寫在同一行。**成分股是凍結的、事後選的，
   偏誤方向是**高估**——「到達 #1 之後平均 +X%」這句話天生偏樂觀。
   `CLAUDE.md` 對持續性數字已經這樣標註，這一項必須沿用同一格式。

另外它第 5 節那句「11 個主題的 Rank-IC 只能當診斷證據，不能當預測證據」——
同意，而且 repo 已經是這樣讀的（B＋C，非 confirmed）。
