> 由規劃端（Cowork）在 sprint 004 併入 `dev` 之後寫。
> 這份問的是**我們怎麼工作**，不是產品該長什麼樣。產品題進 `backlog.md` / `open-questions.md`。

## 一個數字先擺著

五輪 sprint 的產出，按性質分：

| Sprint | 產品面 | 量測／驗證／修正 |
|---|---|---|
| 000 | — | 文件整地 |
| 001 | 故事層資料結構 | breadth NaN 修正、訊號品質三數 |
| 002 | — | 多時間窗 RS、persistence 循環位移檢定 |
| 003 | — | DO-1…DO-6 **全部**在修 002 那個檢定 |
| 004 | narrative schema、籃子面板 | 資料空窗檢查、事後追加兩項修 003 |

**五輪裡有兩輪（002、003）完全沒有產品面產出，其中 003 整輪都在修 002。**

這不是浪費——003 修掉的是「虛無分布被退化抽樣污染，讓每個百分位都偏低」，
那是真的壞掉。問題不在做了這些事，在於**它們吃掉了 DO 的格子**。

## R1 — 「上一輪之後使用者用過產品嗎」這一問沒有牙齒

**物證：**`narratives/` 到 sprint 004 為止只有兩個檔，其中 `2026-09-06.yaml` 是實作端
這一輪寫的樣本。001 就建好了故事層結構，中間隔了三輪，使用者一次都沒有自己寫過第二份快照。

skill 有問這一句，但答案是「沒有」時只要求「DO 至少一項是『讓它更好用』或工程債」。
太軟。`design-v0.2.md` §26 的原話是 **"Do not add features before using the product"**。

**建議：**升級為硬閘門——**連續兩輪沒有新增使用痕跡 → 強制 NO-SPRINT**，
報告只寫「為什麼不開、這段期間 PO 要做什麼、什麼條件重開」。
NO-SPRINT 這個出口已經在 skill 裡了，缺的是一條會真的觸發它的規則。

## R2 — 層次檢查會無限遞迴

**條文：**「若第一層尚未驗證可信（已知正確性問題未修），第二層項目原則上不進 DO。」

**物證：**002 量出持續性 → 003 發現虛無被污染 → 004 發現 percentile 飽和、
各 k 樣本不一致。**每一輪的驗證都會生出下一輪的驗證。閘門不會自己開。**
004 能走出來，是靠規劃端在報告裡明寫「推翻這條判準、開一半」，
而理由不是第一層變可信了，是「擋住使用的東西在第二層」。

**建議：**條文從「L1 沒有已知問題」改成
**「L1 的已知問題**會影響本輪要動的東西**時才擋」**，並要求在報告裡指名是哪幾項、為什麼會影響。
這樣閘門仍然有效（004 的 DO-3 就是被它逼出來的，那是對的），但不會永遠關著。

## R3 — 還債佔掉 DO 的三格

Appetite 管的是本輪的複雜度上限，**沒有任何東西管「上一輪產生的驗證債」**。
003 的三格全部用來還 002 的債；004 三格裡一格是資料完整性，事後又追加兩項還 003 的債。

**建議：**修正**上一輪產生的缺陷**不佔 DO 三格，另立一欄「還債」，
並在報告裡把還債的項數寫出來。**那個數字本身就是訊號**——
連續兩輪還債數 ≥ DO 數，代表上一輪走太快，該降 Appetite 而不是加規則。

## R4 — 「記錄結論避免重複討論」沒有生效

**物證：**`backlog.md` 有一整節「橫斷面動能指標盤點（2026-09-04 評估，結論：不新增）」，
KD／RSC／Mansfield RS／RRG／RSI 全部評估過，開頭還寫著
「**記錄在此是為了避免日後重複討論**」。2026-09-05，PO 又問了同一題。

**不是 PO 的錯。**階段 0 的固定讀取清單有 `backlog.md`，但沒有指明要讀「已評估、不新增」那類段落，
而那些段落離「待排」表很遠。

**建議：**兩件事。
（a）階段 0 讀 `backlog.md` 時明確包含「已評估／已結案」段落。
（b）**PO 問到已結案的題目時，報告要先說「這題在 X 結案，結論是 Y」，再問要不要重開**，
而不是當成新題目重新研究一次。

## R5 — 規劃端被實作端擋下兩次，而報告裡沒有它的位置

**物證（本輪兩次）：**

1. **分支清理的閘門判準寫錯。**規劃端只驗了鏈尾 `do6`，就寫成「四條分支全部驗過」。
   實作端跑出三條非空 diff，停下來回報而不是自行放行。
2. **`revisit` 必填 vs 舊檔不變在 spec 裡自相矛盾。**實作端發現兩條同時成立不可能，
   自己設計了 `REVISIT_REQUIRED_FROM` 的 grandfather 規則並標明是 spec 沒要求的。

skill 的報告格式有「多做了 spec 沒要求的事」，**卻沒有對稱的「規劃端被更正了什麼」**。
這一格是這個分工最有價值的產出——規劃端跑不了測試、看不到型別，本來就會寫錯——
但目前它只存在於對話裡，不會進文件，下一輪讀不到。

**建議：**階段 5 報告固定加一格「**本輪規劃端被更正了什麼**」，與「多做了」對稱。

## R6（小）— 收尾漏了 backlog 的「已完成」表

`backlog.md` 的「已完成」表停在 002；003、004 的項目還留在「待排」或根本沒搬。
skill 的收尾清單有「更新 `docs/sprints/README.md` 索引」，沒有這一項。
留著會讓下一輪重複評估已經做完的事——backlog 自己的「過期規則」正是為此存在。

## 有效、不要動的

- **規則帳（條文／起因／重看）＋ 每輪質疑一條規則。**D11 那次是乾淨的示範：
  物證出現了（`nvhbm` 自述 schema 表達不了），但詮釋是「缺多對多欄位」不是「缺圖結構」，
  所以結論是條文收窄而不是推翻。**沒有規則帳就會直接推翻它。**
- **物證而非斷言。**本輪四次錯誤全部是靠「貼實際輸出」而不是「宣稱通過」抓到的。
- **輸出預算。**003 的報告 585 行是超標的，004 拆出 `evidence.md` 之後 spec 就守住了。
- **NO-SPRINT 這個出口存在。**它只是還沒有一條會觸發它的規則（見 R1）。
