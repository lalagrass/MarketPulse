# Non-goals

**理由才是資產，結論不是。**每一條都寫下「為什麼不做」，因為未來要質疑一條規則時，
需要質疑的是它的理由，不是它的結論。

## 規則 vs 預設值

- **規則**：不可破。破了這個專案就變成另一個東西，或者數字就是假的。
- **預設值**：預設照做，**講得出理由就能推翻**，但必須在 sprint 報告裡說明推翻了什麼、為什麼。

這個區分存在的原因：本專案的限制大多來自多輪 AI review，而 reviewer 的工作就是找問題——
那個迴圈只會加規則、不會刪規則，且那些 reviewer 都沒跑過這個專案的 code。
把想像出來的謹慎跟真正踩過的坑分開，是為了讓限制可以被檢驗。

**每輪 sprint 質疑一條規則**（見 `/marketpulse-sprint` skill）：問「是什麼事情真的發生過才有了這條」，
答不出來的，提議從規則降級為預設值。

## 規則（不可破）

### R1 — 不做綜合評分
不實作 `rotation_score`、加權排名、confidence 分數、alpha 分數或任何複合指標。
主排名永遠是 `rank = cross_sectional_rank(RS20)`。

**理由：**排名一旦有權重就會開始被調，而調權重沒有停止條件——你會一直調到過去的
資料好看為止。可重現、無參數的排名是這個工具唯一的護城河。破了這條，MarketPulse
就變成市面上任何一個調參數的選股器。

### R2 — 不使用未來資料
訊號日 T 只能用 ≤T 的價量，成分股只能用 ≤T-1。

**理由：**破了這條，每一個數字都是假的，而且是那種看起來很棒的假。
已有 `tests/test_future_mutation.py` 守著。

### R3 — 第二層不得改變第一層的數字
故事層（脈絡、股癌、產業鏈）可以決定「要量哪一組股票」，不能改變「怎麼量」。

**理由：**第二層唯一的價值來自於有一個獨立的客觀基準可以對照。一旦敘事影響了
RS20 的計算，兩層就變成同一層，「數字說 A、人說 B」這個資訊來源就消失了。
這條是 R1 的推廣。

**具體反例（010 階段 1 越界提案，已駁回）：**由程式依 `basket` 的 RS20／rank
在 `revisit` 到期時自動把 branch 判為 `confirmed`／`refuted` 並寫回 YAML `log`。
它同時破壞兩件事：第一層的數字回頭改變第二層的內容，且帶日期快照被程式改動之後
不再是「當時人怎麼想」的紀錄。**回看必須由人做，程式最多只能提醒到期。**

## 預設值（講得出理由可推翻）

### D1 — 不做即時／盤中
**理由：**會逼整個資料層從「每天抓一次官方 EOD」改成串流架構，去回答一個
收盤後跑一次就能回答的問題。成本與收益完全不成比例。

### D2 — 不做完整損益回測（進出場、部位、成本、損益曲線）
**理由：**不是技術難，是它會把專案拖進調參數的無底洞。一旦有了損益曲線，
就會忍不住去調 RS 的窗口長度讓曲線好看——那就是在 overfit 過去八個月的台股，
而且會直接侵蝕 R1。
**註：**較輕的「持續性統計」（rank 的自我相關）不在此限，它不模擬買賣。
2026-09-04 討論中曾考慮「前瞻報酬分布」，PO 決定不做，理由是第一層做好即可，
前瞻留給使用者判讀。

**2026-09-06 sprint 007：**005／006 的 `rank-ic` 不牴觸 D2。它是買資訊的診斷
（Spearman(RS_k[T], excess_h[T→T+h])），不進 Brief／radar 的排名、不改 rank、
不模擬進出場或損益。D2 擋的是把前瞻資訊拿去調參數、畫損益曲線；診斷可以量
「這個排名對後面的報酬還有沒有資訊」而不跨過那條線。

### D3 — 不做 RRG
**理由：**`rank` + `rank_delta_5` 已經涵蓋了 RRG 雙軸（強度 × 動能）概念的實用部分。
RRG 增加的主要是視覺複雜度，不是資訊量。
**已確立 2026-09-04。**coding-contract §11 的附帶條件已撤回，矛盾消除。

### D4 — 不做 regime detection / theme regime
**理由：**列在 coding-contract §11。目前沒有具體使用情境驅動它——
在證明第一層的訊號有價值之前，加一層狀態判斷只是增加要維護的東西。

### D5 — 不做個股買賣建議
**理由：**這是一個描述資金流向的工具。跨過去就要面對完全不同的責任，
而且會反過來逼你需要 D2 那種回測來支撐建議。

### D6 — 不重建歷史成分股（point-in-time membership）
**理由：暫緩，非永久排除。**

**2026-09-05 sprint 002 規則質疑（本輪對象）：維持為預設值，但優先序提高。**
問「是什麼事情真的發生過」——現在有具體事件了：sprint 001 量到的持續性數字，
本身就是在「以後見之明選出的成分股」上算的。`themes/v1.yaml` 凍結且橫跨全部歷史，
成分股是知道它們後來的表現之後才選的。這**很可能高估短尺度持續性**
（被選進同一主題的股票本來就傾向同漲同跌）。
破例的代價依然很高（重建歷史成分股會吃掉數個 sprint），所以維持暫緩；
但它從「方法論上比較誠實」升級成「已知會污染一個我們正在用的數字」。

**2026-09-05 再評估（DO-1 結果已出）：優先序再提高一級。**
20 日持續性百分位 81，本來就不顯著；而 D6 的偏誤方向是**高估**，
所以真實值只會更低而不會更高——這個結論不會因為修掉 D6 而翻盤。
真正的問題出在下一步：**要拉長資料窗（目前只有 161 個交易日），就必須同時處理 D6。**
用 2026 年的 `themes/v1.yaml` 回頭量 2023 年，量到的一大部分是「這些股票後來紅了」。
拉長歷史會**放大**這個偏誤而不是稀釋它。
兩者因此不是兩個獨立的 backlog 項目，是同一件事的兩半。
解法不必是「重建歷史成分股」那條貴的路——見 open-questions Q5 的 as-of 快照。

### D7 — 不做 watchlist / Streamlit / 通知 / 排程 / 雲端
**理由：**列在 coding-contract §11。本機、收盤後、手動觸發已經滿足目前的使用方式。

**理由：**自寫的指標要自己驗證，而驗證成本高於使用成本。

目前不列為相依套件。超過單行 pandas 的東西仍須先找現成實作。

### D9 — 不過早抽象
不建 provider framework、plugin 系統、DI 容器、指標註冊表、event bus、策略框架。
**理由：**列在 coding-contract §6、§12。目前程式碼是八個模組的純函式，好讀好改。

**理由：**這是 R1 的軟性版本。常數要改必須有市場概念上的理由，不能有「試了比較好」的理由。
**註：**這條最接近規則，若哪天要動任何一個常數，應先確認是否其實在破 R1。

### D18 — 不用統計分群決定籃子成員

報酬相關性只能用來**提名**候選代號給人挑，不得自動決定籃子成員；
挑中的進 `inferred_symbols`，不進 `named_symbols`。

```text
條文：統計只提名，宣告才產生分類
起因：2026-09-08 研究。規劃端原本要推薦「拿種子代號跑相關性分群」，查完改口
物證：Chan / Lakonishok / Swaminathan, Financial Analysts Journal
      <https://www.lsvasset.com/pdf/research-papers/industry_FAJ.pdf>
      階層式分群的群內相關係數樣本內 0.51、樣本外掉到 0.39；小型股的統計群在
      測試期幾乎與群外無異；標準產業分類（GICS）在樣本外勝出。論文的判讀是
      統計分群抓到的多半是個股特有報酬的相關，那個東西不會延續
詮釋：宣告式分類比統計分群穩。這正好是 named_symbols／inferred_symbols 那條線的
      外部依據——那條線原本只為 R3 而畫
重看：若真的跑了共動提名，並量到自己資料的樣本外衰減
```
